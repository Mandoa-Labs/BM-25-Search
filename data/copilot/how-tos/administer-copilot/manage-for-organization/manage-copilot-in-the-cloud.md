# Managing GitHub Copilot in the cloud for your organization

Enable Copilot in the cloud for your members and control the repositories where it is available.

Copilot in the cloud is a connected experience that lets users start and resume cloud sessions across the GitHub website, GitHub Mobile, Copilot CLI, and the Copilot app. See [GitHub Copilot on GitHub.com and GitHub Mobile](/en/copilot/concepts/copilot-surfaces/copilot-on-github).

The **Copilot in the cloud** policy determines:

* Whether users can access the chat interface or assign work to Copilot on the GitHub website and GitHub Mobile
* Whether users can start sessions in cloud sandboxes from local clients (Copilot CLI and the Copilot app)

This feature is enabled by default. To ensure data security, chat sessions are scoped by default to either a single organization or the user's personal repositories. If you have enabled single sign-on (SSO), users will need to authenticate with SSO to access session data from a repository associated with that organization.

## Enabling Copilot in the cloud for your members

> [!NOTE]
> Copilot policies are also managed at the enterprise level. If your enterprise owner has selected a specific policy, such as enabling a feature everywhere, disabling it everywhere, or enabling it for selected organizations only, you cannot override that setting at the organization level. For information on how policies combine, see [GitHub Copilot policies for enterprises and organizations](/en/copilot/concepts/enterprise/policies).

Copilot in the cloud is enabled by default for organization members assigned a GitHub Copilot Enterprise or Copilot Business license by your organization.

Organizations with Copilot Enterprise or Copilot Business can enable or disable these features for members on the Copilot policies page for their organization. See [Enabling Copilot features in your organization](/en/copilot/how-tos/administer-copilot/manage-for-organization/manage-policies#enabling-copilot-features-and-models-in-your-organization).

* For the "Copilot in the cloud" policy, select "Enabled".
* Optionally, for the "MCP servers on GitHub.com" policy, select "Enabled".

## Controlling automations in your repositories

Automations let users run Copilot sessions automatically, on a schedule or in response to events. See [Copilot automations](/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations).

Automations are allowed by default in repositories where Copilot in the cloud is available. You can control whether automations are allowed in repositories owned by your organization, separately from the Copilot in the cloud policy.

## Managing the agent firewall for your organization

Organization owners can configure the firewall for their organization to determine which external hosts and URLs the cloud agent can access. For more information, see [Customizing or disabling the firewall for GitHub Copilot](/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-the-firewall).
